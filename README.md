# Emerald Host — управляющий бот для Bothost

Исполнитель заданий из общей PostgreSQL и Telegram-бот с единственной командой `/start`. При добавлении проекта на [сайте](https://github.com/creepyside11/hostsait) исполнитель загружает код, устанавливает зависимости, запускает процесс, передаёт BOT_TOKEN и переменные, сохраняет статус и логи. Поддерживает остановку, запуск, перезапуск, GitHub-обновление и удаление.

## Установка на Bothost

1. Подготовьте PostgreSQL: выполните `sql/001_init.sql` из репозитория сайта.
2. Создайте Telegram-бота в @BotFather. Его токен — **только для управляющего бота**, не используйте его же в дочерних ботах.
3. В Bothost подключите этот репозиторий, ветку `main`.
4. В дополнительных настройках включите **«Использовать собственный Dockerfile»**. Это описано в [документации Bothost](https://bothost.ru/docs/custom-dockerfile). Образ содержит Python, venv, pip, git и Node.js/npm. Docker внутри контейнера не требуется и не используется.
5. Заполните переменные ниже, подключите постоянное хранилище `/app/data` при наличии на тарифе. Команду запуска Dockerfile не переопределяйте. Публичный домен, webhook и входящий порт не нужны: все соединения исходящие.
6. Запустите **одну реплику**. Отправьте `/start` управляющему боту, затем добавьте простой проект через сайт и проверьте логи установки и запуска.

| Переменная | Значение |
| --- | --- |
| `DATABASE_URL` | Прямое PostgreSQL-подключение или session pooler с TLS к той же БД, что у сайта; **не transaction pooler** |
| `ENCRYPTION_KEY` | Тот же 64-символьный HEX-ключ, что у сайта |
| `BOT_TOKEN` | Токен управляющего Telegram-бота |
| `SITE_URL` | Полный адрес сайта |
| `TRUSTED_CODE_ONLY` | `true`: явное включение режима для доверенного кода |
| `DATA_DIR` | По умолчанию `/app/data/emerald` |
| `MAX_RUNNING_BOTS` | По умолчанию `10`, уменьшите под RAM вашего тарифа |
| `INSTALL_TIMEOUT` | Лимит каждой команды установки в секундах, по умолчанию `600` |
| `MAX_WORKDIR_MB` | Периодически проверяемый размер каталога одного проекта, по умолчанию `1024` МБ |

`.env.example` — только справочник. В Bothost все значения задаются переменными окружения. Файл `.env` программа не загружает. Пользователь `emerald` запускает исполнителя и дочерние процессы; стартовый скрипт лишь создаёт и назначает владельца каталога данных после монтирования Bothost.

## Как запускается Python

1. Получить ZIP из БД или архив выбранной ветки публичного GitHub.
2. Безопасно проверить пути и размеры, распаковать, найти указанный файл запуска.
3. Создать отдельное виртуальное окружение `.venv`.
4. Если существует `requirements.txt` в корне проекта — выполнить `.venv/bin/python -m pip install --no-cache-dir -r requirements.txt`. Например, `aiogram>=3,<4` будет установлен здесь. Без файла зависимостей шаг пропускается.
5. Запустить `.venv/bin/python -u main.py` (или другой указанный `.py`) с пользовательскими переменными.
6. Писать stdout/stderr установки и бота в логи. Ошибка pip переводит проект в «Ошибка»; процесс бота при этом не запускается.

Для Node.js: `npm ci --omit=dev` с package-lock.json, иначе `npm install --omit=dev`, затем `node index.js` или указанный `.js` файл. Вложенный файл запуска поддерживается; cwd остаётся корнем проекта. Нативные Python-зависимости, которым нужны дополнительные системные библиотеки, могут потребовать изменения Dockerfile и пересборки исполнителя.

## Надёжность и ограничения

- Работает через очередь PostgreSQL, без попыток управлять чужими контейнерами через Bothost API.
- Обрабатывает одно действие одновременно. Установка не блокирует Telegram `/start` и heartbeat. Во время длительной установки следующая операция ждёт; отмена текущей установки через панель не поддерживается.
- Session advisory lock не допускает вторую реплику. При потере соединения с БД исполнитель завершает все известные процессы, чтобы не создавать дубли.
- После перезапуска контейнера незавершённые задания повторяются, боты с желаемым состоянием running запускаются снова. Если локальные файлы потеряны, исходники и зависимости восстанавливаются. Для GitHub берётся текущее содержимое ветки.
- Остановка убивает группу процесса, в том числе его дочерние процессы. Не используйте код, который демонизируется, создаёт новые сессии или пытается обойти управление процессами.
- Работает с polling-ботами; выделенные входящие порты и webhook URL для дочерних ботов не создаются.
- БД хранит зашифрованные настройки, ZIP и ограниченное количество логов. Известные значения переменных и шаблоны Telegram-токенов скрываются; приложение бота всё равно не должно печатать секреты в преобразованном виде.
- **Это не песочница. Только ваши боты и код доверенных друзей.** Все процессы имеют одного пользователя ОС, доступ к общему файловому пространству и общим ресурсам. Код загрузки и установки зависимостей тоже исполняется с этими правами. Регистрация закрыта кодом приглашения на сайте.
- Bothost определяет доступность запуска подпроцессов, диска, сети, RAM/CPU и фактическую страну сервера. Значение `nl` обозначает пул приложения, а не гарантирует физическую локацию. Проверяйте свой тариф. На один тариф нельзя обещать неограниченное количество ботов.
- Весь код/библиотеки исполнителя лежат в `/opt/emerald`, поскольку Bothost может монтировать исходники поверх `/app`.

## Локально

Нужны Linux, Python 3.11+, venv/pip, Node.js 22+ (для Node.js проектов), PostgreSQL. Установите зависимости исполнителя, экспортируйте переменные из таблицы и запустите `python main.py`. `DATA_DIR` укажите доступным для записи. Для автономных тестов Runner достаточно Python и cryptography: `python -m unittest discover -s tests -v`. Тест межъязыкового шифрования также требует соседний checkout `../hostsait` и Node.js.
